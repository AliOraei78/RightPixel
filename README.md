# RightPixel

بازی آموزشی فارسی C# با حساب مستقل، ورود با ایمیل و رمز، PostgreSQL 18، ASP.NET Core 10 و TypeScript/Vite.

دوره شامل ۴۴ مرحله و ۳۱۲ اتاق است: ۳۰۸ اتاق اصلی و چهار اتاق پایلوت در پایان S01، S02، S04 و S05. مرحله‌ها و اتاق‌ها به ترتیب باز می‌شوند. اتاق‌های تکمیل‌شده از نقشه در حالت مرور باز می‌شوند؛ فلش‌ها بخش‌های متن و اتاق‌های تکمیل‌شدهٔ همان فاز را نشان می‌دهند. مرور، امتیاز، وضعیت تکمیل و نقطهٔ ادامهٔ بازی را تغییر نمی‌دهد.

## اجرا

تنظیمات محرمانه در `.env` مستقل و خارج از Git قرار دارند؛ `.env.example` فقط الگو است. تنظیمات SMTP از TicketHub خوانده و مستقل کپی شده‌اند. TicketHub هیچ وابستگی زمان اجرا و هیچ تغییری ندارد.

```powershell
docker compose up -d --build --wait
```

رابط محلی: http://localhost:8085 . فقط پورت وب روی loopback منتشر می‌شود. دیتابیس هیچ پورت عمومی ندارد. اجرای محلی با `RIGHTPIXEL_ENVIRONMENT=Development` است. برای انتشار عمومی، HTTPS را در reverse proxy تنظیم و محیط را `Production` کنید؛ Cookie تولیدی فقط روی HTTPS ارسال می‌شود. حالت Development را عمومی نکنید.

Compose سه نقش جدا دارد: PostgreSQL، سرویس یک‌بارهٔ migration/نصب دوره با اعتبار مدیریتی، و API با نقش محدود `rightpixel`. API رمز مدیر دیتابیس را دریافت نمی‌کند. وب از شبکهٔ داخلی با IP ثابت 192.168.240.10 به API متصل است؛ فقط این proxy برای هدرهای forwarded مورد اعتماد است. در استقرار سفارشی این تنظیم و شبکه را با هم تغییر دهید. Nginx مقدار IP ارسالی کاربر را بازنویسی می‌کند.

حساب تازه با نام، ایمیل و یکی از ۴۸ شخصیت ساخته می‌شود. پس از تأیید ایمیل، بازیکن رمز تعیین می‌کند و ورودهای بعدی با ایمیل و رمز انجام می‌شوند. رمز ۶ تا ۱۲۸ کاراکتر و شامل حرف، عدد و نماد است؛ این حداقل طبق انتخاب کاربر از توصیهٔ اولیهٔ امنیتی کوتاه‌تر است. حساب‌های قبلی بدون رمز از «رمزم یادم نیست / تکمیل حساب» استفاده می‌کنند. اعتبار کد و فاصلهٔ ارسال مجدد ۱۲۰ ثانیه‌اند. هر کد پنج تلاش دارد؛ سقف ارسال پنج بار در ساعت برای هر ایمیل و صد بار برای هر IP است. کد در دیتابیس فقط هش کلیددار دارد؛ کد یا رمز SMTP در لاگ نوشته نمی‌شود. نشست سقف هفت‌روزه و انقضای بی‌کاری ۲۴ساعته دارد؛ «من رو به خاطر بسپار» پیش‌فرض خاموش است و فقط با انتخاب بازیکن Cookie ماندگار ساخته می‌شود. مجوز تعیین رمز یک‌بارمصرف و ۱۰ دقیقه معتبر است؛ بازیابی رمز تمام نشست‌های قبلی را باطل می‌کند.

## ذخیره و بازی

نام نمایشی قابل تکرار و تغییر است؛ شناسهٔ ثابت حساب مالک سیو است. موقعیت دیالوگ، چیدمان معما، پیش‌نویس کارگاه و دور موفق باس در سرور نگه داشته می‌شوند. پیام «ذخیره شد» پس از پاسخ موفق دیتابیس نمایش داده می‌شود؛ آخرین ورودیِ هنوز تأییدنشده ممکن است با خروج ناگهانی از دست برود. deadline اتاق با refresh تمدید نمی‌شود.

پروفایل فقط نام و شخصیت دارد. صدا، حرکت و خروج داخل منوی تنظیمات‌اند. استودیو، تالار انتقام، ورود پشتیبان بازیکن و API ویرایش محتوا حذف شده‌اند. تولید محتوا فقط از منبع پروژه انجام می‌شود:

```powershell
python content/csharp/build_course.py
python content/csharp/build_course.py --check
```

چهار پایلوت: چیدن مسیر اجرای JIT، آزمایش کپی و ارجاع، دنبال‌کردن مسیر شرط و حلقه، و باس سه‌دوره‌ای فاز اول. کد دلخواه روی سرور اجرا نمی‌شود. ZIP کارگاه پس از بازشدن اتاق قابل دریافت است؛ پاسخ مرجع فقط پس از تکمیل همان کارگاه در ZIP می‌آید. انتخاب‌های تعاملی و متن داخل صحنه با HTML قابل دسترس‌اند؛ Canvas فقط گرافیک را رسم می‌کند.

## داده و پشتیبان

دادهٔ PostgreSQL در volume `rightpixel_rightpixel-postgres` و کلیدهای نشست در `rightpixel_rightpixel-keys` هستند. rebuild و `down` داده را حفظ می‌کنند؛ `down -v` داده را حذف می‌کند و برای به‌روزرسانی استفاده نشود.

سیو SQLite قبلی به هیچ حساب جدیدی متصل نشده است. volume قدیمی `rightpixel_rightpixel-data` و پشتیبان `backups/before-multiuser-20261029T165235Z` حفظ شده‌اند. پشتیبان شامل snapshot بررسی‌شدهٔ SQLite، فایل‌های نصب Docker و کد قبل از تغییرات است. imageهای قبلی برچسب `before-multiuser-20261029` دارند.

برای پشتیبان PostgreSQL، فایل باینری را با `pg_dump -Fc` داخل کانتینر ایجاد و با `docker cp` دریافت کنید؛ باینری را از pipeline متنی PowerShell عبور ندهید. کلیدهای Data Protection و `.env` را جداگانه و محرمانه پشتیبان بگیرید. بازیابی باید در دیتابیس تازه و با `pg_restore --exit-on-error` آزمایش شود؛ دیتابیس فعال را برای آزمون بازنویسی نکنید.

## آزمون

بک‌اند روی PostgreSQL واقعی موقت در 127.0.0.1:15438 آزموده می‌شود؛ هیچ آزمونی از دیتابیس TicketHub استفاده نمی‌کند. کانتینر تست را با PostgreSQL 18، کاربر postgres، دیتابیس rightpixel_tests و رمز آزمایشی `rightpixel-test-local-only` بسازید. دیتابیس هر آزمون نام یکتای `rightpixel_test_...` دارد و پس از پایان حذف می‌شود. ایمیل آزمون از سرویس حافظه‌ای استفاده می‌کند؛ هیچ مسیر دریافت کد آزمایشی در API تولید وجود ندارد.

```powershell
dotnet test tests/RightPixel.Api.Tests -m:1 -p:UseSharedCompilation=false
npm run build --prefix src/rightpixel-web
npm run lint --prefix src/rightpixel-web
npm run format:check --prefix src/rightpixel-web
npm run test:media --prefix src/rightpixel-web
npm run test:e2e --prefix src/rightpixel-web
```

آزمون مرورگر API را در همان مرورگر شبیه‌سازی می‌کند تا UI بدون ارسال ایمیل واقعی بررسی شود؛ آزمون‌های بک‌اند، API و PostgreSQL واقعی را پوشش می‌دهند. شبیه‌سازی موبایل معادل آزمون گوشی واقعی نیست. ارسال واقعی ایمیل باید با صندوق تحت کنترل صاحب پروژه بررسی شود.
